# XISURA 1.0.76 模式响应验收

## 修复

- 旧模式的完整预设阻塞后续点击；最新点击立即预览，合并未执行请求，取消尚在等待提交的旧预设。已经开始的硬件事务继续校验，保留原有回退保护。
- 模式与监测共享 IPC 连接及锁，监测驱动采样可占用数秒；增加独立模式通道和固件确认字段 `VerifiedPerformanceMode`，模式确认无需等待完整监测。旧服务缺少字段时继续回读。
- 跟随预设的附属控件写入反复诊断设备身份与依赖；成功写入改为更新控制状态，失败恢复路径保留诊断。
- 传感器更新使用单个后台采样任务和不可变快照；不持有控制锁，采样至少间隔 500 ms。温度保护优先读取即时固件温度，不使用超过 3 秒的传感器温度作为后备。
- 状态提示的自动消失不再占用操作等待；相等的可回读 CPU 参数跳过重复写入，模式重置后重新比较。
- 迟到的监测回读不能覆盖新的固件模式确认；排队中的最新预览不回跳旧模式。

## 安装版实测

目标机：MRID6-23 / MRID6_23_P_V39，Ryzen 7 7745HX + RTX 4070 Laptop，Windows 11 x64。

UI Automation 触发实际按钮；独立 WMI 方法 8 每约 25 ms 读取固件模式，计时始于点击。线值：2=办公，0=游戏，1=狂飙。

| 场景 | 实际固件响应 |
| --- | --- |
| 狂飙 → 办公，单次点击 | 99 ms |
| 间隔约 110 ms 连点办公、游戏、狂飙 | 最后点击后 90 ms 确认狂飙；中间游戏也已读回 |
| 间隔约 410 ms 连续六次切换 | 各次 46、46、50、252、47、237 ms |

服务请求日志显示固件模式确认约 49–54 ms；完整预设最后一轮示例：排队 538 ms、服务 183 ms、回读 68 ms。模式生效与整套预设完成分开计时，不把界面预览当作硬件确认。以上为本机样本，不承诺硬件负载下零耗时。
