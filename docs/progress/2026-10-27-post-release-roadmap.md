# 1.0.110 R3 后续路线图

依据 [当前状态](STATE.md)、[首版支持矩阵](../verification/2026-10-26-usable-release-support.md) 与 [R3验收记录](../verification/2026-10-27-usable-release-r3.md)。当前实机证据限 MRID6-23／7745HX／RTX4070 Laptop／BIOS V35、EC0.35；不代表其他机型兼容。

## 当前可用范围

- **A：已验证实际效果并恢复**：主模式的已记录切换范围、快捷控件中的已验项目、灯光常亮/渐变、颜色/亮度/速度及 Logo 灯。灯光循环已取消；Keep 退出只保留已应用静态值，渐变停在最后一帧。
- **B：窄范围配置可用**：CPU 频率/Boost/停泊、PPT/TDC/EDC、MP1、CO/PBO 等仅限矩阵列明字段和数值；GPU 核心/显存偏移及 V/F 仅限已验单点、127 点读回和精确恢复；GPU 预设仅有记录的 Gaming:1 显存跟随单点。B 不证明负载效果、热稳定性或未测组合。
- **部分流程可用**：主页 18/18 槽仅 Partial 流程观察，不是 18/18 实效通过；配置保存、可靠字段应用与恢复不等于所有子档/槽位效果已验。自动化只覆盖已记录的 AC idle/低负载 Office 单点及配置流程。完整触发组合未证。FAN-01 只验正式 GUI 的空闲 EC/固件交还；Keep 默认关闭，完全退出停止 Follow/AUTO 和动态灯光调度。

## 明确边界

- **D：本版不支持写入**：FAN-02–07 固定 RPM、风扇曲线、双通道联动、最大目标、强冷及风扇预设/跟随；GPU-02 核心锁频、GPU-08 任意电压。直接、预设及 AUTO 写入口关闭。
- **C：只读或不作为写功能交付**：GPU-07 功率只读；GPU-01 显卡模式只显示当前态，MUX/路由切换不支持；HOME-04/05 无线状态枚举可读、开关未验；CPU-01 OEM 温度墙、CPU-09/10/11/13/17 等高级字段只限矩阵明确列出的诊断读值，相关写入不开放。CPU-02/03 SPL/SPPT 写入拒绝。
- 禁止游戏/跑分/压力与热稳定性轨迹、MUX 切换、睡眠/自行重启、驱动安装和 EC 地址盲写；这些限制不转成用户必测项。对任何允许的数值点，先鲜读准确试前值；操作后立即恢复该值并独立读回，失败或取消也执行恢复。

## 分阶段计划

本轮已完成1.0.110真实安装、配置/控制保留、Windows服务生命周期与183文件journal持久化迁移；GitHub正式[v1.0.110](https://github.com/1145911974/XISURA/releases/tag/v1.0.110)已发布，5项资产大小及SHA核验通过；详见[安装发布记录](../verification/2026-10-27-install-github-release.md)。原R3并非.NET自包含，本轮已补齐离线运行库，核心应用DLL SHA未变。安装包尚无正式代码签名；MSI仍有WIX1149服务配置及两项ICE03语言元数据警告，实际升级/运行已通过，不能把这些包装成“已全部完善”。

### P0：安全与交付维护

1. 维护每版安装与GitHub交付证据；把离线运行库、runtimeconfig和归档逐字节检查固化到发布步骤，防止依赖开发机环境或Git换行转换造成误报。仅纳入本版相关变更。
2. 持续维护恢复与权限边界：异常、服务退出、Keep、跨启动状态不得产生无归属写入或静默覆盖用户当前值；D/C 项保持不可写。
3. 保持发布证据可复核：支持矩阵、安装/升级/卸载说明、哈希清单与已知限制同步版本；安装及发布后的检查记录可追溯。
4. 优先清理MSI服务配置/语言元数据警告、完善升级/修复时自定义journal参数继承与迁移验证；正式代码签名需真实证书，不用自签名冒充受信发布者。现有已验运行不为这些后续项反复重建。

**验收证据**：安装程序与运行组件版本一致；启动、托盘退出、重开和卸载/升级结果有记录；源码与交付包 SHA 对应；GitHub 链接及文件可访问；恢复结果证明用户当前状态和受保护配置未被改写；D/C 写入口检查无绕行。

### P1：常用功能可靠体验

1. 优先补主页子档/槽位的实机闭环：明确每槽实际字段、应用结果及准确恢复；18/18 流程观察在逐槽证据完成前保持 Partial。
2. 补齐常用模式与自动化的安全边界证据：只扩展已允许的低风险、非禁测情景；逐项覆盖触发、停止、失败、退出及恢复，未证情景继续标待验。
3. 收敛设置和跨显示环境体验缺口，如真实快捷菜单拖拽、不同 DPI 窗口恢复、真实登录自启；避免把配置保存证据等同运行效果。
4. 保留已验用户体验：灯光常亮/渐变；不恢复已取消的循环。Keep 只保留静态已应用值，退出仍停止 Follow/AUTO。

**验收证据**：每个目标 ID 有范围明确的实机步骤、鲜读值、单点变化、独立读回、立即恢复及恢复后验；主流程有正常退出/重开记录。不能安全验证的项目继续标记未验证，不推定通过。

### P2：高级功能、兼容性与深入优化

1. 对风扇高级控制、GPU 锁频/电压及未知 OEM 字段先完成协议/固件能力、单位、读回、所有权与逆操作合同评估；只有边界充分且风险可控时再提出实现方案，D 项当前继续关闭。
2. 扩展机型、BIOS/EC 兼容范围时逐组合建立证据；单机结论不得外推。优先只读识别与拒绝未知状态，写能力按字段准入。
3. 再评估自动化完整条件/Follow 组合及配置规模体验；只使用许可且可恢复的情景，不以禁测的游戏、跑分、轨迹、MUX、睡眠/重启或驱动操作作为验收条件。
4. 根据实际使用反馈选择深入优化项，记录问题、复现条件、修复及回归证据；不预设性能收益或完成比例。

**验收证据**：每项兼容结论对应明确设备/固件和能力 ID；高级写入需先有独立读回及逆操作证明，再有受控单点、恢复后验与隔离审查。缺少前置合同的项目维持 C/D，不以代码实现或模拟测试宣称实机可用。

各阶段按证据逐项更新 [71项验收台账](CURRENT-ACCEPTANCE.csv)；Partial 保持 Partial，未验证与明确不支持分别记录，不设虚构日期、收益或总体完成率。
